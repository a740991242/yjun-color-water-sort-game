# 魔彩瓶代码实现文档

## 1. 技术栈

- React 19：负责应用挂载和组件生命周期。
- TypeScript：项目类型检查。
- Vite：本地开发、构建和 GitHub Pages 发布构建。
- Canvas 2D：负责游戏主画面、瓶子、水层、倒水动画、粒子和彩虹桥。
- Web Audio / HTMLAudioElement：负责短音效、倒水音效、背景音乐和教学语音。
- Maestro：用于 iOS 模拟器 UI 回归测试。

## 2. 目录结构

```text
.
├── .github/workflows/      GitHub Actions 部署配置
├── .maestro/               iOS 模拟器自动化测试脚本
├── docs/                   项目需求、实现和测试文档
├── public/assets/          游戏运行时音频和图片资源
├── public/assets/brand/    logo、封面、彩虹桥等品牌视觉资源
├── public/assets/voice/    教学朗读语音资源
├── scripts/                资源生成和关卡校验脚本
├── src/mocaiping/          魔彩瓶核心实现
├── src/main.tsx            React 入口
└── vite.config.ts          Vite 配置
```

## 3. 入口与挂载

核心入口在：

- `src/main.tsx`
- `src/app.tsx`
- `src/mocaiping/MocaipingGame.tsx`
- `src/mocaiping/game.ts`
- `src/mocaiping/mocaiping.css`

`MocaipingGame.tsx` 内部维护静态 HTML 模板 `GAME_MARKUP`，挂载后调用：

```ts
initMocaipingGame(host)
```

`initMocaipingGame()` 完成：

- 查询 DOM 节点。
- 初始化 Canvas。
- 初始化游戏状态。
- 加载本地设置。
- 创建背景音乐 audio 对象。
- 加载关卡。
- 计算布局。
- 启动封面动画。
- 绑定事件。
- 启动渲染循环。

组件卸载时会调用清理函数，停止背景音乐、倒水音效、教学语音，取消动画帧并移除隐藏 audio 元素，避免开发热更新或页面切换后残留声音。

## 4. 游戏状态模型

主要状态集中在 `game.ts` 的 `state` 对象中，包含：

- `mode`：当前模式，`easy` 或 `hard`。
- `levelIndex`：当前关卡索引。
- `bottles`：当前瓶子数组。
- `selected`：当前选中的瓶子索引。
- `moves`：当前步数。
- `history`：撤销栈。
- `layouts`：瓶子在 Canvas 中的布局。
- `animation`：当前倒水动画。
- `particles`：粒子效果。
- `celebration` / `finale`：通关与最终通关动画状态。
- `completed` / `failed`：关卡状态。
- `settingsOpen` / `settingsTab`：设置面板状态。
- `musicOn` / `sfx` / `teaching`：音频和教学开关。
- `masterVolume` / `musicVolume` / `sfxVolume` / `voiceVolume`：音量。
- `bestStars` / `bestMoves` / `unlocked`：本地进度。
- `audio` / `musicTrack` / `teachingAudio`：音频运行时对象。

## 5. 关卡数据

关卡定义在 `game.ts` 中：

- `LEVELS`：简单模式关卡。
- `HARD_LEVELS`：困难模式关卡。
- `MODES`：模式入口和关卡集合。

瓶子支持两种写法：

```js
["berry", "mint", "ocean", "coral"]
```

或特殊对象：

```js
{ colors: ["berry", "mint"], capacity: 5, receiveOnly: true }
```

字段说明：

- `colors`：从底到顶的颜色数组。
- `capacity`：容量，默认 4。
- `receiveOnly`：只能接水。
- `pourOnly`：只能倒出。

新增或调整关卡后运行：

```bash
node scripts/validate-levels.js
```

该脚本会检查颜色数量、容量和空位配置，避免明显不可玩的关卡进入版本。

## 6. 核心倒水逻辑

### 6.1 选中瓶子

用户触摸 Canvas 后执行命中检测：

```js
hitTest(x, y)
```

如果未选中瓶子：

- 点空瓶，提示“先选有液体的瓶子”。
- 点有水瓶，设置 `state.selected = hit`，播放拿起音效。

### 6.2 判断是否可倒

`canPour(from, to)` 会判断：

- 来源和目标不能相同。
- 来源瓶存在且有水。
- 目标瓶存在且未满。
- 当前关卡未完成、未失败。
- 特殊瓶规则是否允许。
- 目标为空或顶部颜色与来源顶部颜色一致。

返回值包含：

- `ok`：是否可倒。
- `reason`：不可倒原因。
- `color`：本次倒出的颜色。
- `amount`：本次倒出的层数。

### 6.3 开始倒水

`startPour(from, to, move)` 负责：

- 保存撤销快照。
- 增加步数。
- 清除选中状态。
- 创建倒水动画对象。
- 播放倒水音效。
- 展示教学提示。

倒水动画时长当前为 3 秒。

### 6.4 完成倒水

`finishPour()` 在动画结束后执行：

- 从来源瓶弹出对应层数。
- 推入目标瓶。
- 停止倒水音效。
- 判断是否通关。
- 通关时记录最佳成绩、播放庆祝、展示结果面板。
- 非最后一关自动进入下一关。
- 最后一关启动彩虹桥撒花动画。

## 7. Canvas 渲染

渲染循环由 `requestAnimationFrame(render)` 驱动。

主要绘制内容：

- 背景爱心和底部水面。
- 玻璃瓶主体、瓶口、高光、阴影。
- 每层液体色块。
- 选中、提示、特殊瓶标记。
- 倒水动画中的倾斜瓶、水流、目标瓶上涨。
- 倒水和通关粒子。
- 最终彩虹桥和撒花。

Canvas 尺寸根据容器和移动端视口动态计算，监听：

- `resize`
- `orientationchange`
- `visualViewport.resize`
- `visualViewport.scroll`

## 8. 设置与本地存储

本地存储 key：

```text
mocaiping-settings-v4
```

保存内容包括：

- 当前模式和关卡。
- 音效开关。
- 教学开关、语言、模式。
- 音量。
- 最佳成绩。
- 解锁进度。

背景音乐开关固定不保存，刷新后始终关闭，避免移动端浏览器拦截自动播放。

## 9. 音频实现

### 9.1 背景音乐

背景音乐资源：

- `public/assets/background-music.m4a`
- `public/assets/background-music.mp3`

实现方式：

- 页面初始化时创建隐藏 `<audio>`。
- 优先选择 m4a，mp3 兜底。
- 默认不播放。
- 用户点击音乐按钮后执行 `audio.play()`。
- 停止时 pause 并重置 `currentTime`。

iOS 兼容要点：

- audio 元素不使用 `display:none`，而是移到屏幕外。
- 设置 `playsinline` 和 `webkit-playsinline`。
- 背景音乐开关不持久化。
- 按钮触发链路需要保持在用户手势内。

### 9.2 倒水音效

倒水主音效：

```text
public/assets/pour-water.mp3
```

实现方式：

- 倒水开始时创建 audio 播放。
- 使用淡入避免刺耳。
- 播放期间压低背景音乐音量。
- 停止时淡出或强制停止。
- 如果文件音频播放失败，兜底使用 WebAudio 合成倒水噪声。

### 9.3 拿起/放下音效

当前方案：

- 拿起：`public/assets/pick-bottle.mp3`
- 放下：`public/assets/put-down-bottle.mp3`

实现要点：

- 每次播放创建一个新的短音频对象，避免复用同一个 audio 时 `currentTime` 抢占。
- 画布操作通过 `pointerup` 或 `touchend` 触发，尽量贴近真实用户手势。
- 如果 MP3 播放失败，兜底使用原有 `playTone()`。

### 9.4 教学语音

教学语音由 `TEACHING_LINES` 和 `public/assets/voice/` 资源共同支持。

能力包括：

- 中文。
- 英文。
- 双语。
- 幼宝模式。
- 常规模式。
- 教学朗读开关。

## 10. 封面动画

封面节点为 `.cover-intro`。

实现方式：

- JS 根据屏幕尺寸设置真实图片地址。
- 手机使用 `mocaiping-cover-mobile.png`。
- PC/横屏使用 `mocaiping-cover-desktop.png`。
- 至少展示 1.8 秒。
- 图片加载成功、失败或超时后进入拉开动画。

这样避免 iOS 对 `img { content: url(...) }` 兼容不稳定造成封面不出现。

## 11. 资源生成脚本

### 11.1 背景音乐

```bash
node scripts/generate-background-music.js
```

用途：

- 按指定 tempo、notes、bass 生成背景音乐 mp3/m4a。
- 当前正式背景音乐使用最开始合成的版本。

### 11.2 UI 音效

```bash
node scripts/generate-ui-sfx.js
```

用途：

- 生成拿起瓶子、放下瓶子以及试听版本。
- 当前拿起音效采用轻柔木块点按声。

### 11.3 关卡校验

```bash
node scripts/validate-levels.js
```

用途：

- 检查关卡颜色数量、容量和空位基础配置。

## 13. 已知实现注意事项

- `game.ts` 当前包含大量游戏逻辑，后续可按“关卡、渲染、音频、输入、设置”拆分模块。
- iOS 真机音频表现优先级高于模拟器结果。
- Maestro 无法直接判断是否真的有声音，只能验证 UI 和音频状态文本。
- 短 MP3 在 iOS 快速连续播放仍有偶发吞音风险，当前通过 pointerup/touchend 和新建 audio 对象降低风险。
